---
description: PHASES.md の未完了タスクを GitHub Issue に分解する
argument-hint: フェーズ番号（省略時は現在のフェーズ）
---
対象フェーズ: $ARGUMENTS

1. `docs/PHASES.md` を読み、対象フェーズを決める。引数がなければ「現在のフェーズ」を使う。該当するフェーズがなければ、報告して止まる。未完了（`- [ ]`）のタスクだけを対象にする。
2. `docs/SPEC.md` の関係するセクションを読む。SPEC にないことを issue に足さない。SPEC で決まっていない点は、推測で埋めず、issue の概要に「要確認:」として書く。
3. 重複を調べる。`gh issue list --state all --limit 1000 --json number,title,body` で、closed も含めて全件を取得する。タイトルが `[<タスク番号>]`（分割したものは `[<タスク番号>a]` など）で始まる issue、または「PHASES のタスク番号」が同じ issue があれば、そのタスクの issue は作らない。一覧には「既存」として出す。
4. タスクを issue にする。1 issue = PHASES のタスク 1 つ = PR 1 本で終わる粒度にする。PR 1 本に収まらないタスクは `1-5a`、`1-5b` のように分割し、分割した理由を概要に書く。
5. ラベルを用意する（`gh label create phase-<N> --force`、`gh label create ai-ready --force`）。`--force` なので、何度実行してもよい。
6. 依存される側から順に `gh issue create` で作る。後の issue の本文で番号を参照するためである。
   - タイトル: `[<タスク番号>] <タスクの要約>`
   - ラベル: `phase-<N>` だけを付ける。**`ai-ready` は付けない**（人間が内容を見て付ける）。
   - 本文: `--body-file -` で標準入力から渡す。`.github/ISSUE_TEMPLATE/task.yml` と同じ見出しを、同じ順で使う。

   ```markdown
   ### 概要

   何を作るか。1〜3行。

   ### PHASES のタスク番号

   1-3

   ### SPEC.md の参照セクション

   §8.1、§8.2

   ### 受け入れ条件

   - [ ] テストで確認できる形の条件

   ### 範囲外のこと

   - この issue でやらないこと

   ### 依存する issue

   - #12
   ```

   - 受け入れ条件: 「○○すると××が返る」のように、テストで確かめられる形で書く。
   - 依存する issue: `- #<番号>` を 1 行に 1 つ書く。依存がなければ `なし` と書く。完了済みのタスクには依存させない。
7. 最後に、番号・タイトル・依存関係の一覧を表で出力する（既存の issue も「既存」として含める）。「要確認」を書いた issue があれば明記する。`ai-ready` は人間が付けることを伝えて止まる。実装には進まない。
